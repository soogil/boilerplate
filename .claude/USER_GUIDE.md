# Claude Code 사용자 가이드

> Agent, Skills 등 Claude Code 기능을 효율적으로 활용하는 방법

---

## 1. Subagent 활용법

### 1.1 Explore Agent
코드베이스 탐색, 파일 찾기, 구조 분석에 사용

```
# 사용 예시
"auth 관련 파일들 찾아줘"
"에러가 어디서 발생하는지 찾아줘"
"이 프로젝트 구조 분석해줘"

# 효과
- Claude가 직접 검색하지 않고 Explore agent가 탐색
- 결과만 요약되어 반환
- 토큰 대폭 절약
```

### 1.2 Plan Agent
복잡한 기능 구현 전 계획 수립에 사용

```
# 사용 예시
"새 기능 구현 계획 세워줘"
"리팩토링 계획 만들어줘"
"이 버그 수정 방법 계획해줘"

# 효과
- 구현 전 전체 그림 파악
- 실패 없이 한 번에 구현
- 시행착오 토큰 절약
```

### 1.3 Bash Agent
Git, 빌드, 터미널 작업에 사용

```
# 사용 예시
"git 히스토리 분석해줘"
"빌드 에러 해결해줘"
"패키지 설치해줘"
```

## 2. Skills (슬래시 커맨드)

### 2.1 /commit
커밋 자동 생성

```
# 사용법
/commit

# 또는
"커밋해줘"
"/commit 해줘"

# 효과
- git status, diff 자동 분석
- 커밋 메시지 자동 생성
- 한 번에 완료
```

### 2.2 /review-pr
PR 리뷰 자동화

```
# 사용법
/review-pr 123

# 효과
- PR 내용 자동 분석
- 리뷰 코멘트 생성
```

## 3. 효율적인 요청 방법

### 3.1 파일 경로 명시
```
# 좋은 예 (토큰 절약)
"lib/feature/home/views/main_page.dart에서 색상 변경해줘"

# 나쁜 예 (토큰 낭비)
"메인 페이지에서 색상 변경해줘"
→ Claude가 파일 찾느라 탐색 필요
```

### 3.2 구체적인 위치 지정
```
# 좋은 예
"main_page.dart 45번째 줄 _buildHeader 함수에서 수정해줘"
"UserModel 클래스의 toJson 메서드 수정해줘"

# 나쁜 예
"헤더 부분 수정해줘"
"모델 변환 부분 수정해줘"
```

### 3.3 변경 내용 구체화
```
# 좋은 예
"backgroundColor를 Colors.white로 변경해줘"
"fontSize를 16에서 18로 변경해줘"

# 나쁜 예
"배경색 좀 밝게 해줘"
"폰트 좀 키워줘"
```

### 3.4 범위 명확화
```
# 좋은 예
"이 파일만 수정해줘"
"views 폴더 내 모든 파일에 적용해줘"
"parents_view.dart와 our_story_page.dart 둘 다 수정해줘"

# 나쁜 예
"전체적으로 적용해줘"
"관련된 곳 다 수정해줘"
```

## 4. 작업 유형별 최적 요청

### 4.1 단일 파일 수정
```
"[파일경로]에서 [위치]의 [항목]을 [값]으로 변경해줘"

예:
"lib/theme.dart에서 primaryColor를 #FF5733으로 변경해줘"
```

### 4.2 다중 파일 동일 수정
```
"[파일1], [파일2], [파일3]에서 [항목]을 [값]으로 변경해줘"

예:
"page1.dart, page2.dart, page3.dart에서
WeddingColors.ivory를 Colors.white로 변경해줘"
```

### 4.3 새 기능 추가
```
"[위치]에 [기능] 추가해줘. [상세 요구사항]"

예:
"main_page.dart에 로그아웃 버튼 추가해줘.
우상단에 배치하고 클릭하면 AuthPresenter.logout() 호출"
```

### 4.4 버그 수정
```
"[파일]에서 [증상] 버그 수정해줘. [원인/위치 힌트]"

예:
"login_page.dart에서 로그인 버튼 두 번 눌리는 버그 수정해줘.
isLoading 상태 체크가 없는 것 같아"
```

### 4.5 리팩토링
```
"[파일/폴더]에서 [현재상태]를 [목표상태]로 리팩토링해줘"

예:
"user_repository.dart에서 콜백 방식을 async/await로 리팩토링해줘"
```

## 5. 배포 요청

### 5.1 빌드 + 배포
```
# 좋은 예 (한 번에)
"빌드하고 배포해줘"
"웹 빌드해서 Firebase에 배포해줘"

# 나쁜 예 (분리)
"빌드해줘" → "배포해줘"
→ 두 번의 명령 = 두 배 토큰
```

### 5.2 수정 후 배포
```
# 좋은 예 (수정 여러 개 후 한 번 배포)
1. "A 수정해줘"
2. "B도 수정해줘"
3. "C도 수정해줘"
4. "배포해줘"

# 나쁜 예
1. "A 수정하고 배포해줘"
2. "B 수정하고 배포해줘"
→ 배포 3번 = 토큰 3배
```

## 6. 대화 컨텍스트 활용

### 6.1 이전 작업 참조
```
# 좋은 예
"아까 수정한 파일에서 같은 방식으로 Q2도 해줘"
"방금 적용한 색상 다른 페이지에도 적용해줘"

# 나쁜 예
"parents_story_page.dart에서... (전체 설명 반복)"
→ 이미 알고 있는 내용 재전달 = 토큰 낭비
```

### 6.2 점진적 요청
```
# 좋은 예
1. "Q1 답변 추가해줘"
2. "Q2도 해줘"
3. "나머지도 같은 방식으로 해줘"

# 나쁜 예
"Q1, Q2, Q3, Q4, Q5 전부 다 한번에... (상세 내용 전부)"
→ 한 번에 너무 많은 정보 = 컨텍스트 폭발
```

## 7. 요청 템플릿

### 7.1 기본 템플릿
```
[파일] 파일경로
[위치] 클래스/함수/라인
[작업] 변경 내용
[범위] 이 파일만 / 연관 파일 포함
```

### 7.2 예시
```
[파일] lib/feature/home/views/parents_story_page.dart
[위치] _InterviewAccordion Q1
[작업] brideAnswer를 "처음 인사 오던 날..."로 변경
[범위] 이 파일만
```

## 8. 피해야 할 요청 패턴

### 8.1 모호한 요청
```
❌ "좀 더 예쁘게 해줘"
❌ "최적화해줘"
❌ "전체적으로 수정해줘"
```

### 8.2 과도한 요청
```
❌ "전체 앱 리팩토링해줘"
❌ "모든 파일에서 ~해줘"
❌ "A도 하고 B도 하고 C도 하고 배포까지 해줘"
```

### 8.3 불필요한 확인 요청
```
❌ "이렇게 해도 될까?"
❌ "먼저 확인해줄래?"
→ 명확하면 바로 "해줘"로 요청
```

## 9. 체크리스트

### 요청 전
- [ ] 파일 경로를 알고 있는가?
- [ ] 변경 위치를 특정할 수 있는가?
- [ ] 변경 내용이 구체적인가?
- [ ] 작업 범위가 명확한가?

### 효율적인 작업 순서
1. 여러 수정사항 먼저 요청
2. 확인/테스트
3. 마지막에 한 번 배포

### 대규모 작업 시
1. 계획 먼저 요청 (Plan agent)
2. 단계별로 나눠서 진행
3. 각 단계 완료 확인 후 다음 진행
